2. **Analyse de la consigne et du contrat** `openapi.yml` : 5 opérations attendues en séance 1 — `GET /health`, `GET /health/ready`, `POST /v1/orders`, `GET /v1/orders/{order_id}`, `POST /v1/predictions`. Toutes les erreurs au format `Error`, variables absentes ou en trop → 422.
3. **Choix des options** pour les deux ADR (SQLite ; répertoire versionné).
4. **Découpage du notebook** en couches `domain / abstractions / infrastructure / ml / services / api` (voir [Architecture](../architecture.md)).
5. **Implémentation** :
   - ports `OrderStore` et `ModelRepository` (ABC) ;
   - `SqliteOrderStore` (WAL, `INSERT OR REPLACE` = règle `keep="last"` du notebook), `InMemoryOrderStore` pour les tests ;
   - `FileModelRepository` : `artifacts/models/<X.Y.Z>/model.joblib + manifest.json`, versions immuables, vérification SHA-256 avant chargement (joblib = pickle) ;
   - `OrderService` (génère `CMD-XXXXXXXXXXXX` si `order_id` absent) et `PredictionService` (seuil configurable, latence mesurée) ;
   - API FastAPI : schémas Pydantic calqués sur `components/schemas`, `extra="forbid"`, gestionnaires d'erreurs au format `Error`, composition root `create_app` ;
   - `scripts/train.py` : entraînement séparé du service, publie une version.
6. **Ajustement OpenAPI** : FastAPI ajoutait une réponse 422 `HTTPValidationError` automatique sur `GET /v1/orders/{order_id}` absente du contrat → module `api/openapi.py` qui retire les 422 automatiques.
7. **Vérifications** :
   - `pytest` : **34 tests passent** (store × 2 implémentations, dépôt de modèles dont modèle altéré refusé, service de prédiction sur les commandes d'exemple des cellules 37-38, API, contrat OpenAPI des opérations de séance 1) ;
   - données générées identiques au notebook (vérifié ligne à ligne) ;
   - test de bout en bout avec uvicorn : `/health/ready` → `ready`, `POST /v1/orders` → 202, relecture OK, `POST /v1/predictions` → `oui` (p = 0,94) ;

Légèrement différentes du `metrics.json` du notebook (0,7525 d'accuracy) avec des données identiques : l'écart vient de l'environnement d'exécution (version de scikit-learn / run différent) — à revérifier en relançant `scripts/train.py` sur le poste.
